This plugin setup is optimized for AI-assisted development. It provides one unified `wp-plugin-bp` skill as an Agent Package Manager (APM) package. APM installs the same source into the native locations used by Codex, Copilot, Claude, Cursor, Gemini, OpenCode, Windsurf, Kiro, and Agent Skills-compatible clients.

## How It Works

The AI integration consists of two layers that work together:

### 1. AGENTS.md — The Rulebook

The `AGENTS.md` file in the root directory is the primary instruction set for AI agents. It contains:
- High-level architecture guidance
- Coding standards and conventions
- Quick reference for key primitives
- Pointers to detailed documentation

**This file is your single source of truth** for how AI agents should interact with your codebase.

### 2. `wp-plugin-bp` Skill And WordPress Skills

The package source lives in `.apm/skills/wp-plugin-bp/` and handles:
- Multi-file operations
- Decision trees and conditional logic
- Integration with external tools
- Automatic task routing for natural-language requests

APM deploys the skill to runtime-specific directories. Most clients share `.agents/skills/`; Claude and Kiro use their native skill directories. Do not edit deployed copies directly.

Agents should infer the right task from natural language. For example, "sync this plugin with upstream project conventions" routes to `upgrade`.

## Available Tasks

| Task | Description |
|---------|-------------|
| `upgrade [scope]` | Sync with the latest upstream project conventions. Natural prompts like "update plugin conventions" route here. |
| `translation [lang1 lang2...]` | Update or create translations. Without arguments: updates existing `.po` files. With arguments: creates or updates specific languages. |
| `testing [target]` | Write or debug PHPUnit application tests using wp-env conventions. |
| `action-scheduler [target]` | Add or test Action Scheduler integration. |
| `qa [scope]` | Run configured quality checks and fix errors. |
| `readme [target]` | Update README.md with current plugin information. |
| `wp-skills [skillnames]` | Download and install official WordPress agent skills. |
| `blocks [target]` | Scaffold or maintain Gutenberg blocks. |
| `abilities [target]` | Implement or update Abilities API code. |
| `bundling [target]` | Work on wp-scripts entry points, assets, or enqueueing. |
| `acf [target]` | Add or maintain ACF integration patterns. |
| `sentry [target]` | Add or maintain Sentry integration patterns. |

## Built-in Skills

### wp-plugin-bp

The `wp-plugin-bp` skill is the unified router for plugin workflows. Its `SKILL.md` stays small, and task-specific procedures live in `.apm/skills/wp-plugin-bp/references/`.

The initial Composer package includes `apm.yml` and `.apm/` so setup can run `wp-plugin-bp/scripts/plugin-replace.php` for identity replacement. The manifest version tracks the Demo Plugin release independently from the example plugin's `1.0.0` runtime version.

Setup captures that package version, removes the package-authoring files, and can install the matching Git tag as a dependency. APM then creates a consumer `apm.yml`, writes `apm.lock.yaml`, and deploys the skill. Commit the consumer manifest, lockfile, and deployed files so other contributors receive the same context on clone.

### Install or restore the package

Install the latest package from the upstream repository:

```bash title="Terminal"
apm install JUVOJustin/wordpress-plugin-boilerplate
```

Pin a Demo Plugin release when reproducibility matters:

```bash title="Terminal"
apm install JUVOJustin/wordpress-plugin-boilerplate#v2.3.0
```

APM auto-detects installed agent runtimes. If the project has no detection signal yet, select one explicitly, for example `apm install --target codex JUVOJustin/wordpress-plugin-boilerplate`.

Refresh declared dependencies and verify the deployed files with:

```bash title="Terminal"
apm update
apm audit
```

## WordPress Agent Skills

The WordPress project provides official skills for WordPress development. The `wp-skills` workflow installs requested skill directories as virtual APM packages from `WordPress/agent-skills`:

| Skill | Purpose |
|-------|---------|
| `wp-block-development` | Create, modify, and debug Gutenberg blocks |
| `wp-interactivity-api` | Work with the Interactivity API for dynamic blocks |
| `wp-phpstan` | PHPStan analysis with WordPress-specific rules |
| `wp-project-triage` | Project analysis and task management |
| `wp-rest-api` | REST API routes, auth, and schema guidance |

Ask the `wp-plugin-bp` skill to run the `wp-skills` workflow to refresh these skills or install another official WordPress skill.

## Packages and bundles

The APM package is the primary distribution format because its skill primitive reaches every stable target relevant to Demo Plugin. Prompts, agents, and hooks have narrower runtime support and are not required for the current router.

An APM bundle is useful for offline or controlled distribution, but it is not a substitute for the APM CLI. Package maintainers can create a versioned archive with `apm pack --archive`; consumers still use `apm install` to verify and deploy it. A runtime without APM can use the Agent Skills standard as a manual fallback by copying `.apm/skills/wp-plugin-bp/` from the matching release into its supported skills directory.

## Tips for Effective AI Collaboration

- **Be specific**: Instead of "fix the bug", say "fix the PHP notice in src/Admin/Settings.php line 42"
- **Reference conventions**: Mention "follow the Loader pattern" or "use the enqueue_entrypoint method"
- **Use the `wp-plugin-bp` skill**: It is faster and more consistent than describing the same task repeatedly
- **Update docs**: When you add new patterns, update `AGENTS.md` so future AI interactions benefit
