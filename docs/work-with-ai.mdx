This plugin setup is optimized for AI-assisted development. Its Agent Package Manager (APM) package provides portable foundation instructions and one unified `wp-plugin-bp` skill. APM installs them into the native locations used by Codex, Copilot, Claude, Cursor, Gemini, OpenCode, Windsurf, Kiro, and Agent Skills-compatible clients.

## How It Works

The AI integration consists of two layers that work together:

### 1. APM Instructions — The Rulebook

Portable foundation rules live as focused files under `.apm/instructions/`. They contain only always-on WordPress plugin scope, architecture, asset, and quality guardrails. Task routing, decisions, and procedures belong to the `wp-plugin-bp` skill instead of being repeated in the instructions.

The source `AGENTS.md` keeps producer-only boilerplate context outside `<!-- apm:start -->` and `<!-- apm:end -->`. That context is wrapped in `BOILERPLATE-DOCS` markers and is removed during plugin setup. The producer manifest uses APM's managed-section mode so compiled foundation rules only replace the content between the APM markers.

The foundation instructions intentionally omit `applyTo`. WordPress plugin scope, architecture, scaffold entry points, and quality guardrails must be available while an agent plans a change, before a matching file such as `block.json` exists or is opened. APM therefore treats these rules as unconditional and folds them into the root context. The first instruction defines the active WordPress plugin package root, so the rules still apply correctly when the package is inside a monorepo without affecting sibling applications, themes, libraries, or services. Consumer projects compile the installed instructions into `AGENTS.md` or the corresponding native rule files for their selected runtimes. Do not edit generated rule content directly.

### 2. `wp-plugin-bp` Skill And WordPress Skills

The skill source lives in `.apm/skills/wp-plugin-bp/` and handles:
- Multi-file operations
- Decision trees and conditional logic
- Integration with external tools
- Automatic task routing for natural-language requests

APM deploys the skill to runtime-specific directories in consumer projects. Do not edit deployed copies directly.

Agents should infer the right task from natural language. For example, "sync this plugin with upstream project conventions" routes to `upgrade`.

## Available Tasks

| Task | Description |
|---------|-------------|
| `upgrade [scope]` | Sync with the latest upstream project conventions. Natural prompts like "update plugin conventions" route here. |
| `translation [lang1 lang2...]` | Update or create translations. Without arguments: updates existing `.po` files. With arguments: creates or updates specific languages. |
| `testing [target]` | Write or debug PHPUnit application tests using wp-env conventions. |
| `action-scheduler [target]` | Add or test Action Scheduler integration. |
| `qa [scope]` | Run configured quality checks and fix errors. |
| `readme [target]` | Update README.md with current plugin information. |
| `wp-skills [skillnames]` | Download and install official WordPress agent skills. |
| `blocks [target]` | Scaffold or maintain Gutenberg blocks. |
| `abilities [target]` | Implement or update Abilities API code. |
| `bundling [target]` | Work on wp-scripts entry points, assets, or enqueueing. |
| `acf [target]` | Add or maintain ACF integration patterns. |
| `sentry [target]` | Add or maintain Sentry integration patterns. |

## Built-in Skills

### wp-plugin-bp

The `wp-plugin-bp` skill is the unified router for WordPress plugin workflows. It resolves work against the plugin package root even when installed at a monorepo root. Its `SKILL.md` stays small, and task-specific procedures live in `.apm/skills/wp-plugin-bp/references/`. Detailed guides remain canonical regular files under `docs/`. Task references use normal relative Markdown links to those guides; APM rewrites links that leave the skill so installed references point to the package copy under `apm_modules/`.

The initial Composer package includes `apm.yml` and `.apm/` so setup can run `wp-plugin-bp/scripts/plugin-replace.php` for identity replacement. The manifest version tracks the Demo Plugin release independently from the example plugin's `1.0.0` runtime version.

Setup captures that package version, removes the package-authoring files, and can install the matching Git tag for the Codex target. APM then creates a consumer `apm.yml`, writes `apm.lock.yaml`, deploys the shared skill, and compiles the foundation instructions into `AGENTS.md`. Additional runtimes can be added later with APM. Commit the consumer manifest, lockfile, and deployed files so other contributors receive the same context on clone.

### Install or restore the package

Install [APM](https://microsoft.github.io/apm/getting-started/installation/) if it is not already available.

Install the latest package from the upstream repository:

```bash title="Terminal"
apm install JUVOJustin/wordpress-plugin-boilerplate
```

Pin a Demo Plugin release when reproducibility matters:

```bash title="Terminal"
apm install JUVOJustin/wordpress-plugin-boilerplate#v2.3.0
```

APM auto-detects installed agent runtimes. If the project has no detection signal yet, select one explicitly, for example `apm install --target codex JUVOJustin/wordpress-plugin-boilerplate`.

Compile the installed instructions explicitly so `AGENTS.md` is populated even when Copilot is the only auto-detected runtime:

```bash title="Terminal"
apm compile --force-instructions
```

Refresh declared dependencies and verify the deployed files with:

```bash title="Terminal"
apm update
apm audit
```

APM 0.25.0 has a known false-positive where `apm audit` reports dependency skill files with rewritten package-relative links as drift ([microsoft/apm#2154](https://github.com/microsoft/apm/issues/2154)). The deployed links still resolve into `apm_modules/`; do not copy the canonical guides into the skill to silence this report.

## WordPress Agent Skills

The WordPress project provides official skills for WordPress development. The `wp-skills` workflow installs requested skill directories as virtual APM packages from `WordPress/agent-skills`:

| Skill | Purpose |
|-------|---------|
| `wp-block-development` | Create, modify, and debug Gutenberg blocks |
| `wp-interactivity-api` | Work with the Interactivity API for dynamic blocks |
| `wp-phpstan` | PHPStan analysis with WordPress-specific rules |
| `wp-project-triage` | Project analysis and task management |
| `wp-rest-api` | REST API routes, auth, and schema guidance |

Ask the `wp-plugin-bp` skill to run the `wp-skills` workflow to refresh these skills or install another official WordPress skill.

## Packages and fallbacks

The Git-based APM package is the primary distribution format because its instruction and skill primitives reach every stable target relevant to Demo Plugin. Prompts, agents, and hooks have narrower runtime support and are not required for the current router.

Do not publish the default `apm pack` output as a complete distribution of this package. APM bundles include packable primitives, but they do not automatically include the non-primitive `docs/` files reached through package-relative links. If an offline or non-APM artifact becomes necessary, generate a standalone skill archive during the release from the matching tag and copy the required guides into that temporary artifact. Do not commit generated guide copies to the source tree.

A runtime without APM can use the Agent Skills standard as a manual fallback by copying `.apm/skills/wp-plugin-bp/`, `.apm/instructions/`, and the referenced `docs/` files from the same release into the corresponding locations in the target project.

## Tips for Effective AI Collaboration

- **Be specific**: Instead of "fix the bug", say "fix the PHP notice in src/Admin/Settings.php line 42"
- **Reference conventions**: Mention "follow the Loader pattern" or "use the enqueue_entrypoint method"
- **Use the `wp-plugin-bp` skill**: It is faster and more consistent than describing the same task repeatedly
- **Update rules**: When the plugin foundation changes, update the relevant file in `.apm/instructions/`
